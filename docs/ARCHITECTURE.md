# Architecture

Icarus is a TypeScript app with no front-end framework and no bundler. `tsc` compiles `src/` to ES modules in `dist/`; the browser loads them directly. A small Node HTTP server serves the built files, the marketplace API and the coach.

```
data/
  demo/                   Fictional, labelled demonstration listings (generated by scripts/generate-demo-data.mjs)
  runtime/                Submitted requests (git-ignored; DATA_DIR in production)
src/
  shared/                 Runs in the browser and on the server, pure and unit-tested
    audience.ts           Kids / adults / older adults: labels, age bands, guardian and nutrition rules, safety text
    fitness/
      types.ts            Domain types (profile, plan, session, workout, exercise, audience)
      exercises.ts        Catalog: muscles, equipment, cues, mistakes, photos, variations, audiences, categories
      exercise-instructions.ts  Step-by-step instructions from Free Exercise DB (generated)
      programs.ts         Plan templates (incl. Play & Move, Active Ageing), prescriptions by level, goal and audience
      session.ts          Workout engine: timestamp-based timers, pause, settle
      stats.ts            Streaks, summaries, personal bests, units
      storage.ts          Repository over a key-value store, with validation and import/export
    marketplace/
      types.ts            City, Gym, MembershipPlan, Professional, PackageTemplate, Quote
      pricing.ts          Effective monthly price, totals, payment schedule, savings, package quotes
      search.ts           Gym query parsing and search (one implementation for server and tests)
      geo.ts              Distance, place resolution (names, postcodes), coarsening to ~1 km
      requests.ts         Request input schema and field validation (shared by form and server)
      local.ts            On-device state: audience, location, saved items, comparison, requests, meal notes
    coach/                Coach request/reply contracts and the offline coach
  server/
    main.ts, app.ts       HTTP server, security headers, host/origin/token checks, rate limits, static files
    config.ts             Environment parsing (AI providers, data directory, webhook, map, support)
    marketplace/
      provider.ts         MarketplaceProvider interface and DemoProvider (validated JSON)
      requests.ts         RequestStore: JSON lines, hashed access tokens, retention, optional webhook
      routes.ts           /api/marketplace, /api/gyms, /api/professionals, /api/geocode, /api/requests
    providers/, prompt.ts, subprocess.ts   AI coach adapters
  web/
    main.ts               Shell, navigation and mobile menu, routes, background timer settling
    core/                 DOM builder, router, store, coach and marketplace API clients, cues
    ui/                   Components, icons, brand mark, photo demonstrations, marketplace building blocks
    views/                One file per screen (home, gyms, memberships, coaching, request, nutrition,
                          library, profile, info, workouts, plus the training screens)
    styles/               tokens, base, components, views, market, motion (concatenated at build)
    static/media/         Exercise photographs (WebP)
```

## Data flow

1. **Audience first.** The first visit opens `#/welcome`. The choice is stored on the device and read through `store.audience()` by every screen, the plan generator, the library and the coach context. The server enforces the same rules on requests (package, plan and professional audiences; guardian consent for children).
2. **Discovery reads.** Screens call `market.*` in `web/core/market.ts`, which fetches `GET` endpoints and caches them per page load. Gym search runs on the server with the shared `searchGyms`.
3. **Requests.** Forms validate with the shared `validateRequest` for instant feedback. The server checks the exact structure (`isRequestInput`), validates again, checks every referenced gym, plan, package and professional exists and suits the audience, and **builds the quote itself** from the listing. It stores the request and returns a reference and a one-time access token. The browser keeps both; the server keeps only the token's SHA-256 hash.
4. **Status.** `received` (stored), `forwarded` (accepted by the configured webhook) or `withdrawn` (contact details erased). There is no `confirmed` state: only the provider can confirm, outside Icarus.

## HTTP API

| Method and path | Purpose |
|---|---|
| `GET /api/health` | Liveness. |
| `GET /api/config` | Per-process token, available coaches, map and support settings, whether the data is demo. Never includes keys. |
| `GET /api/marketplace` | Provider name, demo flag, cities, packages. |
| `GET /api/gyms?…` | Search. Parameters: `lat`, `lng`, `radius`, `q`, `audience`, `city`, `min`, `max`, `months`, `facilities`, `categories`, `classes`, `trainers`, `open24h`, `early`, `accessible`, `reviewed`, `sort`. Invalid values are dropped. |
| `GET /api/gyms/:id` | Full gym with its trainers and nutritionists. |
| `GET /api/professionals?role&city&audience&gym` | Directory. |
| `GET /api/professionals/:id` | Profile and the gyms they work at. |
| `GET /api/geocode?q=` | Resolve a typed place against the provider's gazetteer. |
| `POST /api/requests` | Create a membership enquiry, coaching request, general enquiry or support message. Needs `X-Icarus-Token` and JSON. 201, 400, 409, 415, 422 (with `fields`), 429. |
| `GET /api/requests/:ref` | Status, with `X-Request-Token`. |
| `DELETE /api/requests/:ref` | Withdraw and erase contact details, with `X-Request-Token` and `X-Icarus-Token`. |
| `POST /api/coach` | AI coach. See [AI_PROVIDERS.md](AI_PROVIDERS.md). |

## Key decisions

- **An integration boundary for listings.** Screens never know where gyms come from. `MarketplaceProvider` has four methods; the demo provider reads and validates `data/demo`. A live provider (database or partner API) implements the same interface. The demo flag travels with every record so the interface can label it.
- **The server owns prices.** Clients send ids, never amounts. Quotes are recomputed from the listing and the professionals' rates on every request.
- **No fake states.** No login screen, no payment form, no "confirmed" booking, no ratings without a verified source, no "best value" badges. Unavailable things say so (for example the map without a tile server).
- **Typed workouts, not markup.** The coach returns a validated workout object and the app renders everything itself with `textContent`. `scripts/lint.mjs` bans `innerHTML` and similar APIs.
- **Timestamp-based timers.** Timers store end times; `settle()` applies anything that ended while the app was away.
- **One store, validated persistence.** `AppStore` wraps `Repository`; every read and write is validated, and on-device marketplace state is validated field by field so one bad item never wipes the rest.

## Security model

- Binds to `127.0.0.1` by default. Binding elsewhere requires `ALLOWED_HOSTS`; `Host` and `Origin` are checked on every request.
- A random per-process token must accompany every non-GET API request. It blocks cross-site posts; it is **not** user authentication.
- Static files come from an allow-list of `dist/web` and `dist/shared` paths and extensions; source, `.env`, data, prompts and skills are never served. Photos and fonts are cached for a week.
- Content Security Policy `default-src 'self'` with no inline scripts; the configured map tile origin is the only external image source. `X-Frame-Options: DENY`, `nosniff`, `no-referrer`, and `Permissions-Policy` with camera, microphone and payment off and geolocation limited to this site.
- Requests: strict schema, server-side quote, honeypot, 10 per 10 minutes per client address, 256 KB body cap, owner-only file permissions (`0600`, directory `0700`), hashed access tokens compared in constant time, automatic deletion after the retention period, contact details erased on withdrawal. Only the reference and forwarding outcome are logged, never contents.
- AI requests are rate limited and capped in flight; provider errors are mapped to friendly messages; keys are never returned; CLI providers run without a shell or tools.
